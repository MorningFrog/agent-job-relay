# Current limitations

- Linux and Windows x86_64 have verified native runtimes. Windows native launch needs breakaway; a cleanup job can use the verified same-user local CIM daemon bootstrap. Policies denying PowerShell/CIM, restricted tokens and provider limits can require an external-terminal fallback. Windows ChatGPT Desktop same-chat continuation is verified with Full access; restricted terminal binding can fail with access denied and single-command authorization remains unverified. macOS instance identity/lifecycle remain unimplemented. Native Windows CI/release checks passed for the published baseline; each new candidate requires its own native/package gates.
- Codex CLI integration provides MCP tools plus a durable notification inbox. It does not start/resume an Agent automatically. No public app-server writer is owned by this program. No authentication or model invocation is performed.
- ChatGPT Desktop transport is opt-in, private and experimental. v0.1.8 is verified with ChatGPT Desktop on Linux and Windows, including same-chat continuation after task completion. Additional host versions, results completed while the host is closed, real multi-day renewal and receiver deduplication remain separate qualifications. An ack remains accepted_by_host; no adapter automatically confirms resume. See [live verification](live-e2e.md).
- Explicit host/session identities are supplied by the trusted caller. The private API cannot independently attest them. Socket fingerprint/lease changes require refresh or rebind; no magical historical conversation discovery.
- Job attempt=1. Idempotent submission returns the original job; it does not rerun failure. Use a new key/job for a deliberate rerun. Ambiguous launches become orphaned after a 5-second grace period and are never auto-replayed.
- Runner writes terminal state directly to SQLite while daemon is absent. Lost runner lock means orphaned, not success. SIGKILL/power loss cannot run Rust cleanup; Linux parent-death kills the direct workload, but descendants can escape process groups or remain after runner death. Audit external side effects before deliberately submitting again. Graceful cancellation handles non-daemonizing process groups, not adversarial containment.
- A machine reboot stops processes; persisted jobs are classified on restart, never promised to keep executing across shutdown. Fault injection simulates vanished locks/stale boot identity; actual power-loss/ENOSPC VM tests pending.
- Disk write failure is a failed job with diagnostics where DB remains writable. If SQLite itself cannot commit due to disk/full/corruption, recovery may only classify unknown/orphaned. No offline result journal. Unreleased source adds consistent local database/log backups and new-profile restore; these do not guarantee recovery of a terminal commit that never reached SQLite.
- Default maximum eight active jobs; no waiting pool beyond this quota, tuning config, structured progress, interactive stdin/PTY, schedules, SSH or artifacts.
- Per-stream logs cap at 16 MiB, then drain/discard. Text queries use lossy UTF-8; byte cursors can split multibyte characters. Unreleased source automatically compresses eligible cold history/logs; archived history is retained indefinitely and no destructive purge is shipped.
- Every durable record is bounded by quotas but disk is not a reservation system. Unreleased schema v9 archives eligible jobs/targets/attempts without discarding history, preserves session identities and limits only live session registrations. Cold records, archived logs and historical inbox files still consume space. Dispatch permits four concurrent attempts across chats, with one live claim per logical destination. Four slow destinations can occupy all slots for their bounded three-second attempts. Idle cross-process completion discovery can take up to the one-second fallback interval before database/dispatch work; in-process writes wake workers immediately. Native gates and installed-package qualification are separate checks; see [implementation status](IMPLEMENTATION_STATUS.md).
- At-least-once delivery: a host may execute a request even if ack is lost. Stable IDs are provided; host deduplication is not proven. Rebind cancels future claims, not effects already transmitted externally.
- Setup supports Codex TOML, generic mcpServers JSON and an owned local plugin marketplace entry. Local install/uninstall and offline bootstrap/update manage native/plugin files with receipts; no guessed ChatGPT settings format, OS package, service manager or destructive purge is shipped. Installation/cache replacements now have explicit journal-based repair; interrupted setup/marketplace writes, uninstall, pre-journal staging and older unjournaled operations can still need inspection. The CLI only refreshes explicitly selected unchanged profiled caches; host registry/enablement/removal remain host-owned. Source changes do not update installed/cached files. The isolated Codex CLI 0.164.0 loader discovers 22 tools for source 0.1.10; real installed MCP continuation has separate user-confirmed evidence. The v0.1.8 local Linux ChatGPT Desktop workflow is verified; see [live evidence](live-e2e.md). Source templates alone contain no native executable.
- The current local Codex bundle uses `.codex-plugin/plugin.json` and `.mcp.json` with an absolute installed native command. Cached MCP and terminal wrappers both need that managed installation to remain; historical native copies in new caches are not used by the launcher. Portable root MCP was not discovered and plugin-root command variables were not expanded by the tested CLI loader. Offline bootstrap is an explicit local development operation, not automatic host bootstrap or a directly installable marketplace ZIP (ADRs 0004/0007).
- Current Linux daemons spawn from the procfs self-executable link, surviving image pathname replacement, not gaining new code until restarted. An already-running legacy daemon with an unlinked executable needs an explicit idle restart. New client preflight detects this condition and refuses before submitting another job; no silent restart, state switch or failed-workload replay occurs.
- Source/offline delivery remains supported alongside published npm packages and the self-hosted marketplace. Offline hashes do not authenticate the publisher, declare a minimum libc version or download a build; use a trusted compatible Linux artifact. Old caches without the runtime profile need host refresh before managed cache refresh. Directory replacement journals permit checked forward repair; multi-directory/configuration updates remain separate and are not crash-atomic. The npm candidate includes native bytes and records minimum glibc; it uses no secondary native downloader or install hook. Published 0.1.9 installation and OIDC provenance are verified; each subsequent release still needs maintainer qualification. OpenCode V1 has an experimental packaged plugin verified with actual Bun name/version install and 1.19.4 interfaces through a loopback registry with a simulated model; real provider/restart/V2 checks remain open. Claude Code has an inbox-only source framework with synthetic helper/MCP-entry checks and no actual Claude account/loader test. Community tests and PRs are requested. Independent OS installers and package repositories are cancelled. Official directory submissions remain in TODO.md; subsequent preparation/publication runs remain maintainer-only and manually authorized.

Convenience support: `start --wake` / MCP wake_me=true remove manual registration when current host context is inherited. They cannot infer identity in an ordinary terminal or shared MCP process. Use the current ChatGPT Desktop Agent terminal tool when MCP lacks those variables. Automatic sessions lease for 24 hours and opt into delivery-time renewal after probing the same endpoint fingerprint/owner/capability. No periodic host polling is added. Changed endpoints or invalidation need explicit same-chat recovery; manual/legacy registrations default to no renewal. Real multi-day expiry remains unverified; automated expiry tests use fault injection.

Installed/generated MCP uses shared-host mode and an explicit caller binding for spec.session; binding objects also supply the captured workspace, with full=true for complete MCP diagnostic records. ChatGPT Desktop obtains it from the current terminal, while OpenCode uses actual tool context. Live acceptance covers the published baseline rather than every later API convenience change; see [live evidence](live-e2e.md). A local terminal is required; cloud chats without one cannot bind.

Early 0.1.0 daemons without IPC shutdown can be stopped by the 0.1.2 client's verified Linux pidfd/SIGINT path. It requires proc access, pidfd support and a recognized `agent-job-relay` executable in daemon mode. Renamed binaries or failed identity/health checks are refused, with no force-kill fallback. Use the updated source executable with `daemon stop --install-root` to avoid an old installed launcher or wrong shell state; the real install still needs an explicit update.

Host packages require >=0.1.6 core (Windows OpenCode requires >=0.1.7); OpenCode npm candidates depend on the matching packaged runtime, while Claude still requires separate development setup; Codex offline export does not package them. Older executables cannot interpret plugin_bridge records despite unchanged SQLite v6. OpenCode uses public prompt admission with bounded in-process dedupe, not persistent exactly-once delivery or automatic confirmation of model execution. It must explicitly rebind after bridge replacement. Claude wake remains unavailable; no guessed resume command, private ChatGPT Desktop fallback, hooks or channels are shipped. See [host plugins](host-plugins.md).

Unreleased data maintenance runs only while the daemon is running; it is not a system scheduler. Soft hot budgets cannot force archival of active work, unresolved deliveries or unexpired recoverable dead letters. The 10,000-job submission guard applies to hot history. Local daily backups retain three verified snapshots by default; they share the profile disk and need independent copying for disk-loss protection. Active output is a bounded prefix, not an atomic filesystem snapshot. Files outside managed database/log storage, host configuration and raw inbox receipt files are excluded. Linux/Windows maintenance behavior is tested; physical power-loss/ENOSPC and prolonged-load qualification remain open. See [data maintenance](data-maintenance.md).

Unreleased 0.1.10 bundles a default-on authenticated loopback Web UI and runner-owned monitor rules. Linux/Windows native and installed-package checks pass; real mid-run host continuation is not yet qualified. Each rule revision triggers once and must be explicitly rearmed; 16 rule identities and 128 revisions each bound its retained configuration history. Conditions are literal output matches, silence and elapsed time. Browser closing removes live visual feedback while durable alerts/local stops continue. Persisted observation timestamps can be stale after abrupt runner loss or storage contention; silence alone is not a hang diagnosis. Database write failure can prevent durable monitoring/control, and no new disk-loss journal is promised. See [runtime monitoring](runtime-monitoring.md).
