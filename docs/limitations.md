# Current limitations (0.1.4 development milestone)

- Linux x86_64 is the only locally compiled and process-tested runtime. Windows named-pipe ACLs/Job Objects and macOS instance identity/lifecycle are not implemented. Other OS runtime requests explicitly fail. CI is configured but has not been run remotely; it is not evidence of platform support.
- Codex CLI integration provides MCP tools plus a durable notification inbox. It does not start/resume an Agent automatically. No public app-server writer is owned by this program. No authentication or model invocation is performed.
- Desktop transport is opt-in, private and experimental. Automated transport tests use fake hosts; CLI and installed MCP same-chat continuation have user-confirmed live evidence with read-only persisted-record correlation. Earlier CLI results identify Desktop 26.1021.22027 / Ubuntu 26.04; the later MCP report did not reconfirm those version fields. Plugin-browser installation, current host-version compatibility, in-flight daemon interruption, Desktop restart/rebind and delivery-failure recovery remain separate checks. An ack remains accepted_by_host; no adapter automatically confirms resume. See [live evidence](live-e2e.md).
- Explicit host/session identities are supplied by the trusted caller. The private API cannot independently attest them. Socket fingerprint/lease changes require refresh or rebind; no magical historical conversation discovery.
- Job attempt=1. Idempotent submission returns the original job; it does not rerun failure. Use a new key/job for a deliberate rerun. Ambiguous launches become orphaned after a 5-second grace period and are never auto-replayed.
- Runner writes terminal state directly to SQLite while daemon is absent. Lost runner lock means orphaned, not success. SIGKILL/power loss cannot run Rust cleanup; Linux parent-death kills the direct workload, but descendants can escape process groups or remain after runner death. Audit external side effects before deliberately submitting again. Graceful cancellation handles non-daemonizing process groups, not adversarial containment.
- A machine reboot stops processes; persisted jobs are classified on restart, never promised to keep executing across shutdown. Fault injection simulates vanished locks/stale boot identity; actual power-loss/ENOSPC VM tests pending.
- Disk write failure is a failed job with diagnostics where DB remains writable. If SQLite itself cannot commit due to disk/full/corruption, recovery may only classify unknown/orphaned. No offline result journal or backup/export yet.
- Default maximum eight active jobs; no waiting pool beyond this quota, tuning config, structured progress, interactive stdin/PTY, schedules, SSH or artifacts.
- Per-stream logs cap at 16 MiB, then drain/discard. Text queries use lossy UTF-8; byte cursors can split multibyte characters. No automatic retention or purge.
- Every durable record is bounded by quotas but disk is not a reservation system. Historical jobs/targets/inboxes and manually retried attempts need future retention tooling. Dispatcher is serial; a failing host may delay other wakes by up to its 3-second bounded attempt.
- At-least-once delivery: a host may execute a request even if ack is lost. Stable IDs are provided; host deduplication is not proven. Rebind cancels future claims, not effects already transmitted externally.
- Setup supports Codex TOML, generic mcpServers JSON and an owned local plugin marketplace entry. Local install/uninstall and offline bootstrap/update manage native/plugin files with receipts; no guessed ChatGPT settings format, OS package, service manager or destructive purge is shipped. Interrupted operations can need inspection. The CLI only refreshes explicitly selected unchanged profiled caches; host registry/enablement/removal remain host-owned. Source changes do not update installed/cached files. The isolated Codex CLI 0.164.0 loader discovers 20 tools; real installed MCP continuation has separate user-confirmed evidence. Plugin-browser installation remains unverified; see [live evidence](live-e2e.md). Source templates alone contain no native executable.
- The current local Codex bundle uses `.codex-plugin/plugin.json` and `.mcp.json` with an absolute installed native command. Cached MCP and terminal wrappers both need that managed installation to remain; historical native copies in new caches are not used by the launcher. Portable root MCP was not discovered and plugin-root command variables were not expanded by the tested CLI loader. Offline bootstrap is an explicit local development operation, not automatic host bootstrap or a directly installable marketplace ZIP (ADRs 0004/0007).
- Current Linux daemons spawn from `/proc/self/exe`, surviving image pathname replacement, not gaining new code until restarted. An already-running legacy daemon with an unlinked executable needs an explicit idle restart. New client preflight detects this condition and refuses before submitting another job; no silent restart, state switch or failed-workload replay occurs.
- Source build/offline local Plugin development only. Offline hashes do not authenticate the publisher, declare a minimum libc version or download a build; use a trusted compatible Linux artifact. Old caches without the runtime profile need host refresh before managed cache refresh. Multi-directory updates are not crash-atomic. No online native downloader or host install hook exists. Claude Code and OpenCode plugin integrations are planned, not implemented. Independent OS installers and package repositories are cancelled. Future official plugin platforms remain in TODO.md; no publication/submission occurs during development.

Convenience support: `start --wake` / MCP wake_me=true remove manual registration when current host context is inherited. They cannot infer identity in an ordinary terminal or shared MCP process. Use the current Desktop Agent terminal tool when MCP lacks those variables. Automatic sessions lease for 24 hours and opt into delivery-time renewal after probing the same endpoint fingerprint/owner/capability. No periodic host polling is added. Changed endpoints or invalidation need explicit same-chat recovery; manual/legacy registrations default to no renewal. CLI shortcut live evidence is user-attested and version-specific; the reviewer correlated private artifacts without independently observing the UI. MCP wake_me=true has fake-host automation and real process coverage, but no separate real-host shortcut validation. Same-chat recovery and delivery-time renewal have isolated fake-host/installed-process evidence only; no new real restart or multi-day execution is claimed. Multi-day expiry is fault-injected in tests.

Installed/generated MCP uses shared-host mode and obtains a fresh current-terminal session key for spec.session. Two-caller fake-host tests and a user-confirmed live MCP task/continuation cover that route. It requires a local terminal and is unavailable in a cloud chat without one. Latest read-only MCP health reports runtime 0.1.4 and matching installed/active state; the original submission route and UI continuation remain user-attested. This does not establish plugin-browser installation, current host-version compatibility or another platform. No equivalent repeat or manual crash matrix is required.

Early 0.1.0 daemons without IPC shutdown can be stopped by the 0.1.2 client's verified Linux pidfd/SIGINT path. It requires proc access, pidfd support and a recognized `agent-job-relay` executable in daemon mode. Renamed binaries or failed identity/health checks are refused, with no force-kill fallback. Use the updated source executable with `daemon stop --install-root` to avoid an old installed launcher or wrong shell state; the real install still needs an explicit update.
