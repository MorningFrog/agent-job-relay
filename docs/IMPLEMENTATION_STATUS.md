## Implemented behavior

| Area | Current behavior |
|---|---|
| Native execution | Explicit argv/shell, validated cwd/env/timeout, typed Job/Run states with unchanged SQL/JSON vocabulary, durable original IDs/attempt, unchanged-key idempotency, independent runner/process groups/Windows Job Objects, live-Linux adopted-child cleanup, flushed/synchronized logs, conservative orphan handling and no execution replay |
| Batch | 1–16 independent specs with distinct keys, indexed partial admission and safe retries; eight execution slots per profile; persisted deadlines (24 hours by default, explicit no-wait override) admit up to 64 extra waiting jobs, preserving FIFO launch reservations and independent rules/stop/notifications |
| Scoped goal consent | Structured `needs_confirmation` before wait/job creation, one negotiated MCP or Agent question, natural user reply, original scope and transactional budget; blocked/inactive state gates new work without invalidation, controller read loss retains consent/waits, host Resume reuses the request, withdrawal works offline and stale observations cannot overwrite concurrent decisions; expiry/revocation/restore fences remain |
| Goal handoff | Originating native pause plus revision-fenced confirmation before `waiting`; frozen exact-run membership, accounting-preserving restoration, merged notification, deletion/cancellation/uncertain-mutation fences. Source 0.1.19 `goal_wait_pending` recovers an outstanding original handoff without a new question/binding, exposes continuation actions/revisions in CLI/MCP/Web and briefly settles a live final ACK locally before another round. Consent-free pause remains unavailable |
| Goal feedback | Requested notifying rules temporarily restore the original goal for a report, then require originating native re-pause/confirmation on the same wait. Original request/members/accounting remain; 32 attempted cycles, 60-second minimum interval and a five-minute re-pause deadline bound control. Intermediate ACKs cannot consume the final notification; completion supersedes unsent feedback or follows its re-pause. Source 0.1.19 admission also fences ordinary submission through feedback re-pause after consent slots are exhausted |
| Remote tasks | Runtime 0.1.21 command views show saved launch workloads, separate local/remote directories and identities, workload-first bounded summaries and full hot/cold command search; attach metadata stays explicitly unavailable without a protocol change. Runtime 0.1.20 alert-only `remote_alert` subscriptions bridge typed remote rules directly to the origin with transactional event cursors/Outbox, original provenance, backlog coalescing, cooldown/budgets and live-observer capability fencing. Pinned native launch/attach over bounded authenticated stdio, origin IDs, durable launch keys, byte cursors/reconnect and exact-run control; read-only fixed GitHub Actions attempt with bounded job/current-step snapshots and an attempt-specific Web link |
| Storage/maintenance | SQLite WAL/FULL/foreign keys, bounded workers/reserved reads, short transactions, guarded forward migrations, legacy log prefixes plus checksummed bounded recent native segments, transparent cold archives with single-snapshot task inspection, daily verified local backups and new-profile restore without execution replay. Runtime 0.1.20 fresh disk-pressure samples default to 512-MiB warnings/64-MiB new-admission refusal, retaining original-key retries, existing work, stopping and terminal persistence |
| Monitoring/progress/Web | Independent runner rules and bounded tails/evidence; structured stages/steps/metrics with durable sequence/cooldown/terminal fences; default-on authenticated loopback React/Vite panel sharing CLI/MCP controls; bounded one-second shared viewer samples and ten-second timestamped health, with explicit reads/controls direct; narrow icon navigation and inline selected-task details; Compact task/alert page headers show only current running/queued counts and explicit connection state, independently of loaded history/search/selection; source workflow discovers/reuses one same-profile tab beside the originating chat and handles task/credential navigation in place |
| Task titles | Optional CLI `start --title` and MCP/JSON `spec.title` for single/batch submission, bounded Unicode validation, persisted Job/inspection/compact views and title search/list/detail headings; unnamed history uses compact command/project hints while details retain full commands. Omitted titles preserve historical idempotency bytes without migration |
| Feedback receipts | Read-only single/batch admission and detailed CLI/MCP/Web receipts expose persisted rules, application/source evidence and active recorded target/lease capabilities. Source 0.1.19 `visibility` adds sample-based ten-minute quiet-output/missing-notifying-rule advisories, retained in compact inspection and CLI human output; stale/incomplete/terminal/external evidence remains separate. Keep original IDs without host probes, rule insertion, consent changes or claims of Agent execution. Runtime 0.1.20 feedback-tab cards show rule application/source/target limits and editable stage/time presets; concise attention hints remain above the output-first terminal and explicit Save uses existing monitor admission |
| Long-task Agent guidance | Source 0.1.19 workflow, caller-binding/MCP results and OpenCode system guidance plan useful captured output and a few milestone/progress or one-shot elapsed reports before long submissions. Honor explicit completion-only preferences and actual goal-feedback authorization; verify admitted rules and repair the original job without replay. Autonomous installed-host adoption remains unqualified |
| Result inspection | Compact default MCP task results and CLI `inspect --compact`, original identities/timing, 2-KiB per-stream excerpts, three event excerpts, bounded progress, independent notification/goal diagnostics and evidence cursors; complete detail through `full=true`, ordinary CLI JSON and HTTP. Runtime 0.1.20 recovery plans retain original IDs/revisions/expiry and select goal handoffs before ordinary notification recovery; exact-profile command argv is read-only |
| Retained logs | New native exec/shell runs retain each 16-MiB prefix plus four 1-MiB recent segments, checksummed absolute ranges/gaps and final partial publication; CLI/Web bounded text export, no overwrite in CLI, verified archival and locked per-file backup copies. Old runs/remote observer copies retain previous limits. Runtime 0.1.20 literal search preserves absolute offsets/context/gaps and a fixed end, joining contiguous retained blocks only |
| Delivery/recovery | Transactional Event/Outbox, original IDs/TTL/attempts, per-chat claim exclusion, bounded retry, same-chat recovery and verified same-endpoint opted-in renewal; host acceptance remains distinct from execution |
| Caller identity | Fresh actual terminal/tool context, explicit workspace/session bindings, shared MCP never infers a caller from its process environment; cooperative identity is not host attestation |
| Installation/update | Runtime 0.1.14 provides `ajr update` for the global npm CLI and matching official Git marketplace/plugin, with preview/exact-version/CLI-only options, mandatory online CLI prerequisite, schema/downgrade fences, compatible Linux active-run continuation and recorded forward retry. `ajr uninstall` stops idle daemons by default, rejects active work unless `--force` confirms shared exact-run stops, and removes the CLI last while retaining data. Local native updates keep their checked restart/backup/cache route; OpenCode remains host-managed |
| Stable runtime instructions | Cached skills and MCP initialization point to current `instructions`; retained managed MCP verifies receipt/profile/image and forwards catalogs/calls/native input, including same-version changes, without uncertain-call replay or cache scanning |
| Host packages | Experimental private ChatGPT Desktop adapter; Codex CLI inbox-only; OpenCode V1 public session bridge; Claude scaffold inbox-only pending account-backed loader evidence |
| Release delivery | Shared Linux/Windows npm runtime, OpenCode package and self-hosted marketplace; local `finalize_release.py --version <unused-x.y.z>` validates availability, synchronizes Cargo/npm/plugin versions and pins, then runs delivery gates before dated CHANGELOG archival. Failed gates keep version edits with notes pending; interrupted synchronization supports explicit-version retry. Reviewed committed notes feed manual immutable Prepare/Publish/Check workflows. See the [script index](../scripts/README.md). No independent OS installers |

Submissions/register operations start the selected daemon on demand. Doctor/status do not. Windows daemon-only CIM bootstrap authenticates both endpoints and avoids services/elevation; runners still require native breakaway. Configuration/marketplace writes are individually atomic, not a cross-file transaction. Rust 1.89 all-target compilation is verified on Linux; native behavior gates use stable Rust separately.
Runtime 0.1.20 CLI/MCP/Web search spans hot and validated archived records with bounded scan cursors, status/directory/time filters and read-only stopped-profile access. See [inspection/search](runtime-monitoring.md) and [disk policy](data-maintenance.md).
