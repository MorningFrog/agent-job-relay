## Implemented behavior

| Area | Current behavior |
|---|---|
| Native execution | Explicit argv/shell, validated cwd/env/timeout, typed Job/Run states with unchanged SQL/JSON vocabulary, durable original IDs/attempt, unchanged-key idempotency, independent runner/process groups/Windows Job Objects, live-Linux adopted-child cleanup, flushed/synchronized logs, conservative orphan handling and no execution replay |
| Batch | 1–16 independent specs with distinct keys, indexed partial admission and safe retries; eight active jobs per profile, independent rules/stop/notifications |
| Scoped goal consent | Structured `needs_confirmation` before wait/job creation, one negotiated MCP or Agent question, natural user reply, original scope and transactional budget; blocked/inactive state gates new work without invalidation, controller read loss retains consent/waits, host Resume reuses the request, withdrawal works offline and stale observations cannot overwrite concurrent decisions; expiry/revocation/restore fences remain |
| Goal handoff | Originating native pause plus revision-fenced confirmation before `waiting`; frozen exact-run membership, accounting-preserving restoration, merged notification, deletion/cancellation/uncertain-mutation fences. Consent-free pause remains unavailable |
| Goal feedback | Requested notifying rules temporarily restore the original goal for a report, then require originating native re-pause/confirmation on the same wait. Original request/members/accounting remain; 32 attempted cycles, 60-second minimum interval and a five-minute re-pause deadline bound control. Intermediate ACKs cannot consume the final notification; completion supersedes unsent feedback or follows its re-pause |
| Remote tasks | Pinned native launch/attach over bounded authenticated stdio, origin IDs, durable launch keys, byte cursors/reconnect and exact-run control; read-only fixed GitHub Actions attempt with bounded job/current-step snapshots and an attempt-specific Web link |
| Storage/maintenance | SQLite WAL/FULL/foreign keys, bounded workers/reserved reads, short transactions, guarded forward migrations, capped logs, transparent cold archives with single-snapshot task inspection, daily verified local backups and new-profile restore without execution replay |
| Monitoring/progress/Web | Independent runner rules and bounded tails/evidence; structured stages/steps/metrics with durable sequence/cooldown/terminal fences; default-on authenticated loopback React/Vite panel sharing CLI/MCP controls; bounded one-second shared viewer samples and ten-second timestamped health, with explicit reads/controls direct; narrow icon navigation and inline selected-task details; source workflow discovers/reuses one same-profile tab beside the originating chat and handles task/credential navigation in place |
| Feedback receipts | Read-only single/batch admission and detailed CLI/MCP/Web receipts expose persisted rules, application/source evidence and active recorded target/lease capabilities. Keep original IDs on diagnostics failure; distinguish local/inbox/host/goal/terminal/exhausted states without probing hosts or claiming Agent execution |
| Delivery/recovery | Transactional Event/Outbox, original IDs/TTL/attempts, per-chat claim exclusion, bounded retry, same-chat recovery and verified same-endpoint opted-in renewal; host acceptance remains distinct from execution |
| Caller identity | Fresh actual terminal/tool context, explicit workspace/session bindings, shared MCP never infers a caller from its process environment; cooperative identity is not host attestation |
| Installation/update | Runtime 0.1.14 provides `ajr update` for the global npm CLI and matching official Git marketplace/plugin, with preview/exact-version/CLI-only options, mandatory online CLI prerequisite, schema/downgrade fences, compatible Linux active-run continuation and recorded forward retry. `ajr uninstall` stops idle daemons by default, rejects active work unless `--force` confirms shared exact-run stops, and removes the CLI last while retaining data. Local native updates keep their checked restart/backup/cache route; OpenCode remains host-managed |
| Stable runtime instructions | Cached skills and MCP initialization point to current `instructions`; retained managed MCP verifies receipt/profile/image and forwards catalogs/calls/native input, including same-version changes, without uncertain-call replay or cache scanning |
| Host packages | Experimental private ChatGPT Desktop adapter; Codex CLI inbox-only; OpenCode V1 public session bridge; Claude scaffold inbox-only pending account-backed loader evidence |
| Release delivery | Shared Linux/Windows npm runtime, OpenCode package and self-hosted marketplace; manual immutable Prepare/Publish/Check workflows. No independent OS installers |

Submissions/register operations start the selected daemon on demand. Doctor/status do not. Windows daemon-only CIM bootstrap authenticates both endpoints and avoids services/elevation; runners still require native breakaway. Configuration/marketplace writes are individually atomic, not a cross-file transaction. Rust 1.89 all-target compilation is verified on Linux; native behavior gates use stable Rust separately.

## Release and support boundaries

npm/GitHub **0.1.14** is the public baseline. Its Linux payload requires glibc **2.34** or newer; local developer builds can require a newer glibc and must not replace the sealed release payloads. Preserve candidate bytes/receipts; changed runtime/package bytes require a new version and candidate. See [release handoff](release.md#current-release-handoff).

Windows goal/controller, direct native confirmation UI, full real-model multi-round restoration, changed-host goal handling and long-duration savings need separate qualification. Host goal generation/CAS is unavailable. Actual results completed while Desktop is closed, receiver deduplication and multi-day renewal remain open. Claude account-backed loading, OpenCode real-provider/V2, stronger containment, disk-loss qualification and cross-file install recovery remain in [TODO](TODO.md). No adapter automatically records `confirmed_resumed`.
