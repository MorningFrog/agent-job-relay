## Release and support boundaries

Source **0.1.25** has passed local preparation and remains unpublished; its candidate must be built from reviewed main through manual preparation. npm/GitHub **0.1.24** is public with independently verified original bytes/latest, source Tag, eight original assets, local receipt and isolated public installation/native/OpenCode checks. It retains formal Woodpecker candidate #42 and source `baf9a7b`. The Web UI main/manual release workflow defaults to dry-run and coordinates original preparation/reuse, preview, staging, explicit human npm approval, GitHub finalization and independent checks. Six obsolete individual CI publication workflows are removed; the five automatic `_ci-*` and six preparation `_release-*` workflows remain alongside the single Release All entry. The deployment UI displays labeled Release parameters/defaults and groups internal workflows; native permission/submission behavior remains authoritative. The Actions manual backend is unavailable; remaining references are a cleanup task. Ordinary CI cannot publish or seal formal candidates. Release Linux payloads require glibc **2.34** or newer; developer builds can require newer glibc and cannot replace original release bytes. Preserve published notes/dates/Tag/candidate/receipts; a failed verification never undoes publication. See [release handoff](release.md#current-release-handoff).

Goal wake-up and usually successful pause/resume have user-reported sustained-use evidence, with occasional resume failure still unresolved. Windows goal/controller, direct native confirmation UI, a specifically observed full real-model three-round workflow, goal intermediate feedback/native re-pause, changed-host goal handling and measured long-duration savings need separate qualification. Host goal generation/CAS is unavailable. Actual results completed while Desktop is closed, receiver deduplication and multi-day renewal remain open. Claude account-backed loading, OpenCode real-provider/V2, stronger containment, disk-loss qualification and cross-file install recovery remain in [TODO](TODO.md). No adapter automatically records `confirmed_resumed`.
