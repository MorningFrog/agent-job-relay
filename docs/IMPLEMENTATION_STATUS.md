Submissions and explicit session registrations start the per-state daemon on demand; doctor/status do not. `daemon start [--install-root]` starts/reuses only the selected daemon without a job/session, and `daemon stop` leaves runners/results independent. Windows can use a verified same-user local CIM helper when host cleanup blocks direct creation; policy/token denial provides an outside-terminal fallback. No persistent task/service is installed. Configuration and ownership receipts are individually atomic, not a cross-file transaction.

The binary keeps process initialization in `src/main.rs`, command syntax in `src/cli/args.rs` and profile selection/dispatch in `src/cli/mod.rs`. Shared behavior stays in library modules; the CLI reorganization preserves commands, defaults, output and runtime semantics. See the [source map](architecture.md#source-map).

## Installed runtime and release handoff

The 0.1.11 short CLI is not published; online npm installation resolves 0.1.10. The sealed Actions candidate verifies `ajr` without changing real installations. Global CLI installation and host plugin installation remain separate; no alias, PATH edit or installation hook is injected.

AgentJobRelay **v0.1.8** is verified with **ChatGPT Desktop on Linux and Windows**, including same-chat continuation after task completion. Windows verification uses Full access; restricted-mode binding remains a separate qualification. Users should follow the [latest published installation](installation.md#quick-install-the-latest-release); [source installation](source-install.md) ([简体中文](source-install.zh-CN.md)) is an alternative local development route.

Host packages and community acceptance are described in [host plugins](host-plugins.md) and [CONTRIBUTING.md](../CONTRIBUTING.md). OpenCode V2 has a research map only; Claude needs account-backed community verification. The existing offline Codex bundle does not contain those source host packages. Older binaries cannot interpret `plugin_bridge` session records despite the unchanged schema/IPC versions.

The GitHub repository is public. `scripts/prepare_release.py` creates allowlisted tarballs, marketplace ZIP and checksums; `scripts/check_release.py` and `scripts/check_windows_packages.mjs` test installed candidates and actual host loaders. The manual workflow builds Windows MSVC/static CRT and Linux on Ubuntu 22.04, recording actual ELF symbol requirements; the sealed 0.1.11 Linux candidate requires glibc 2.34, while the local source binary requires glibc 2.39. Hashes establish integrity, not publisher provenance.

For 0.1.11, [Release All dry-run](https://github.com/MorningFrog/agent-job-relay/actions/runs/40715714094) qualified original candidate **40715744368**, sealed as latest. Downloaded checksums/inventory, version/pins, Linux/Windows native targets, source/run identity and release notes pass review; actual OIDC preview passed for both packages. Preserve those exact bytes for the original release. Current Unreleased batch/remote/runtime/package/CHANGELOG changes are outside the candidate and cannot use its documentation-only recovery exception; a release containing these changes needs a new version and qualification/candidate. The [release handoff](release.md#current-release-handoff) gives preview/publication boundaries. Publication and the public checker require the separate maintainer-authorized step; no 0.1.11 npm upload, tag or GitHub Release was created.

## Material limitations and next work

- Windows runners still require native breakaway. The daemon-only CIM route cannot bypass local policy/token restrictions. ChatGPT Desktop terminal binding needs host access; the verified Windows workflow uses Full access. macOS native execution/IPC is unimplemented.
- ChatGPT Desktop uses an experimental private interface and trusted caller identity, not host attestation. Codex CLI is inbox-only; offline cached MCP requires the stable original installation path.
- Runner death or escaped descendants can leave unknown effects. Stronger containment, controlled disk/power-loss tests, independent-storage backup automation, destructive history-purge design and cross-file installation recovery remain pending; see [limitations](limitations.md) and [security](security.md).
- External tasks are source-only and require a future qualified candidate. Native remote commands need a copied executable/private profile or a separately implemented contract adapter; SSH and external-task real-host continuation are separate qualifications.
- Offline delivery is not authenticated online distribution. Cache refresh requires explicit snapshots; legacy/pre-journal remnants and interrupted uninstall need separate handling.
- Monitor/Web UI/schema v9 behavior still needs real running-alert host qualification. The 0.1.11 npm alias and Windows shim pass native/package CI; the sealed manual candidate and OIDC preview also pass. Rules fire once per revision, require rearming for another alert, and provide literal/silence/elapsed conditions. Remaining tasks stay in [TODO.md](TODO.md).
