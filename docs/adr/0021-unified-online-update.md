# ADR 0021: Unified online CLI and host-plugin maintenance

## Decision

Use standard global npm registration as the required online ChatGPT Desktop/Codex installation prerequisite. `ajr update` selects one exact published version, updates that global npm prefix and installs its release-tagged marketplace/plugin through public Codex CLI commands. The first plugin installation uses the same command. Keep exact-version plugin runtime pins, existing stable skill entry points and original profiles. Native offline bundles and OpenCode's host-managed dependency retain their existing lifecycle.

The native CLI parses maintenance arguments and returns a bounded request to its npm launcher. The original native process exits before npm replaces package files. The launcher stages and verifies the exact target tarball/native image before replacement and installs those same bytes globally. Its copied target helper serializes installation/startup, pins original daemon peers and validates active jobs against the target schema/contract without migration. Compatible Linux runners continue under original IDs; active Windows package replacement and incompatible migration are refused. It restarts only previously online profiles with verified installed bytes. The installation lock stays held until the controller durably records the outcome and acknowledges release. A lost controller never authorizes workload replay or package rollback.

`ajr uninstall` removes the online plugin, unshared official marketplace and global CLI in that order. It stops idle selected/default daemons by default. Ordinary removal rejects active work before shutdown; `--force` uses the shared durable manual-stop API, confirms exact-run terminal state and the original local runner's exit/lock release, then proceeds. Read-only observation never cancels its external target. Removal never restarts stopped daemons or purges task data. Unconfirmed stops retain the runtime. Native offline removal retains its existing preview/`--apply` contract.

Public host list commands establish marketplace and installed-plugin state. Only the official Git source with an unmodified checkout at its matching release tag is eligible; local/ZIP/native, foreign and changed same-name sources are refused. Codex's exact untracked `.codex-marketplace-install.json` is host metadata only when it is a bounded regular file whose Git source, release ref, HEAD revision and empty sparse-path list match that checkout. Tracked edits, other untracked paths, malformed/mismatched records and symlinks remain refusals; the updater never edits or removes the record itself. Completed stages, original marketplace identity/version and the selected Codex executable/configuration home are recorded privately in the selected profile; a changed host selection fences retry. Separate update/uninstall journals pin unfinished work and prevent switching operations until it completes. Retry reconciles observable host outcomes and continues forward; the CLI is removed last so partial host failures remain recoverable. There is no host cache scanning, configuration-file rewrite, automatic installation hook, custom PATH edit or silent profile migration.

## Rationale and limits

Coordinating npm and the host through one command removes separate version selection while preserving npm's standard command registration and the host's ownership of plugin state. Exact-version plugin pins keep historical cached entries predictable. Reconnect/restart remains necessary to load the new plugin and MCP catalog; updating files alone does not establish same-chat continuation.

The verified Codex CLI exposes no disabled-preserving reinstall or marketplace compare-and-swap. An outdated disabled plugin fails before mutation, and concurrent manual marketplace edits remain unsupported. Updates cover the selected profile and default Codex/OpenCode profiles, without discovering arbitrary custom profiles. npm, marketplace and plugin changes are individually recoverable steps rather than one cross-file transaction. An incomplete journal `.new` file requires explicit inspection. Native Windows package/self-removal with held images and actual Desktop refresh need independent evidence. Other custom profiles and concurrent manual host/package maintenance remain outside automatic discovery/serialization.

## Regression coverage

Native tests cover active/schema/downgrade fences, runner-preserving daemon handover, default idle shutdown, forced exact-run stops without purge, startup/daemon/installation exclusion, preserved history, read-only preview and controller loss. Public-host fixtures cover first install, unchanged retry, partial catalog replacement, disabled/foreign/modified sources and lost installation acknowledgement without blind replay. Installed npm checks cover actual active-run package replacement and forced self-removal; actual Codex loader checks separately exercise public plugin removal in disposable repository-local state; simulated host responses do not qualify actual Desktop UI behavior.
