# Security and data ownership

[Documentation index](README.md) · [Limitations](limitations.md) · [Data maintenance](data-maintenance.md)

Trusted single local user; this executes arbitrary commands with that user's permissions. It is not a sandbox, permission broker or multi-user service. No telemetry, public TCP execution API or automatic host discovery. The 0.1.12 remote tasks use explicitly configured authenticated stdio transports and pinned remote identities.

## Local state and process permissions

Linux state/root directories require same owner and mode 0700; socket 0600 and peer UID check. Files are created under umask 077. Locks and log files use O_NOFOLLOW/O_CLOEXEC. Existing symlink database/configuration/receipt files are rejected. Keep the state directory on a local filesystem supporting SQLite WAL and OS file locks. Do not put it in a shared or attacker-controlled tree. Same-UID malicious processes can read state and invoke commands: out of scope. Ancestor directory replacement by the same user is not a filesystem sandbox.

## Command execution and private data

Commands default to argv execution. Shell requires explicit choice, and cwd is canonicalized and validated. Limits: 8 active jobs, 10000 hot jobs, 1000 connected/unexpired session registrations, 16 targets/job, 256 args, 64 environment overrides, 64 KiB spec, 8 KiB event payload, 16 MiB per stdout/stderr file, bounded frames and result pages. Extra output is drained/discarded and truncation recorded. Automatic maintenance archives eligible history and rotates verified backups; it never purges archived history. Monitor disk space; large retained histories can still consume substantial storage. CPU/memory quotas and escaped-daemon process containment are not provided.

Current-source Linux cleanup runs only inside the live runner after waiting for its direct workload. It reads that runner's own task-local child inventories, verifies each adopted child's current parent and signals a pinned pidfd; it does not scan process names or same-user processes. Failure/deadline cannot produce success. This also cleans adopted session escapes while the runner survives, but cannot run after runner SIGKILL or power loss and does not provide adversarial containment. Buffered output writes must flush successfully before synchronization; storage errors are explicit and cannot authorize execution replay.

Full inherited environment is not stored; explicit override values are stored in the private database and omitted from status output. Command arguments, working directories, logs and environment overrides can contain secrets. Do not pass secrets in argv; logs are not automatically secret-masked. Do not publish state, logs, setup backups or receipts. Output/event payloads are untrusted data and are never executed as internal instructions. ChatGPT Desktop prompts contain only stable job/event metadata, not command output.

## Configuration ownership

Setup changes only the owned agent-job-relay MCP entry, with private adjacent receipt/lock/backup files. It preserves other settings and refuses modified or unowned entries. Default dry-run has no writes; --apply is explicit consent. JSON formatting may be normalized; TOML foreign comments are preserved. Backups may contain unrelated secrets and remain private. Config and receipt are individually atomic, not a cross-file transaction: interrupted setup may require reviewing the backup/receipt; it fails closed rather than taking over. No service, global PATH, sudo, real config modification or network publishing is performed by development tests.

## Caller identity and notifications

ChatGPT Desktop endpoint is explicitly supplied, owned and peer-checked; private API compatibility and receiver dedupe remain uncertain. Registration stores a socket fingerprint, not cryptographic host attestation. It never scans other sessions, reads credentials, injects binaries or creates a second Codex writer.

Current-context convenience accepts only inherited CODEX_THREAD_ID and CODEX_APP_TOOLS_PIPE_PATH for opted-in --wake/wake_me=true. These remain trusted caller declarations, not host attestation. Shared MCP processes cannot choose per-chat destinations and must use explicit bindings or the current Agent's terminal-tool CLI. Host capability is probed before executing a wake-enabled job. A missing context/capability is an error, not a weaker notification fallback. On-demand launch uses a private startup lock and a detached daemon boundary; only absent/refused sockets trigger launch. No system service is installed. Shutdown remains owner-only IPC and is excluded from MCP discovery.

Installed plugins and generated MCP entries enforce shared-host mode: no inherited chat environment can authorize an implicit wake. A fresh exact session key comes from the current terminal's inherited context and is passed explicitly over MCP. This remains the trusted local-user model, not cryptographic caller attestation. The CLI binding's --brief form omits private endpoint/registration details.

## Native installation and cache ownership

Online `ajr update` verifies the selected global npm prefix and PATH entry, pins one published version and serializes replacement with a private copied native helper. The target helper validates the existing active schema/job contract; compatible Linux runners continue while incompatible migration and active Windows package replacement are refused. Original daemon peers are revalidated before shutdown and only previously online profiles restart. New online plugins require global CLI registration without an automatic installation hook. Only an unmodified official Git marketplace is eligible; private stage journals pin its identity/version and the original Codex executable/configuration home for forward retry. npm and host writes are separate operations, without rollback or public host compare-and-swap; do not edit marketplace registrations concurrently. Offline/native and OpenCode state are not moved or discovered through cache scanning. Online `ajr uninstall` stops idle daemons by default, refuses active work unless `--force` first uses the durable stop API and confirms exact-run/local-runner exit, removes the CLI last and never purges task data. Separate pinned update/removal journals prevent unfinished operations from overlapping. Shared/foreign host content is retained.

Local installation stores a state-only profile and SHA-256 ownership receipt, not live host identity or credentials. The wrapper and MCP pin the same profile despite unrelated AJR_STATE_DIR exports. Replacements stage new files and retain backups; modified or foreign contents and symlink paths are refused. Data cannot be nested in the install tree. Runtime locks serialize binary changes; active jobs block file replacement before any daemon stop. Applied updates pin the online daemon, shut it down gracefully and launch the validated installed payload afterward. Directory replacements publish private durable journals; explicit repair checks snapshots/profiles/hashes, respects installation/cache locks and refuses altered files. Repair only finishes the recorded replacement, preserves backups/data and never rolls back schemas or stops daemons. Multi-directory/configuration changes and multi-file removals remain non-atomic. Unjournaled/old interruptions require inspection. Host user enablement/removal remains managed by the host. The CLI only refreshes explicitly supplied cache snapshots after checking their installation/state/platform, complete file set and hashes; it never scans or purges caches. Modified/foreign/legacy caches are refused and backups retained. Marketplace setup edits only the owned entry and preserves the existing catalogue and other plugins.

## Windows startup and process isolation

Windows state/files use the current owner SID and a protected DACL admitting only that SID and LocalSystem, with reparse/junction refusal. Local pipes reject remote clients and authenticate peer process-token SIDs; process creation time fences reused PIDs. Daemon/runner CreateProcess disables inherited handles, and runner-owned Job Objects contain workloads before user execution and kill their descendants on runner death. Native creation refuses non-breakaway host jobs. Daemon-only automatic CIM bootstrap validates both process instances/images/SIDs/integrity levels/privilege inventories and private pipe ACLs, rejects restricted/AppContainer/low-integrity tokens and transfers environment in memory without persisting it. No scheduled task, service, elevation, remote target or alternate user is introduced. Local-policy failures remain explicit, with a same-profile external-terminal fallback. See [ADR 0012](adr/0012-windows-on-demand-bootstrap.md). Node/Bun host bridges pin the exact server process and secure owner/DACL before registration; the core verifies the pipe ACL before every exchange. See [ADR 0011](adr/0011-windows-native-runtime.md). Windows write-through publication is not a physical power-loss qualification.

## Linux upgrades and explicit shutdown

Linux internal child launch executes the mapped image through the procfs self-executable link, retaining the same program image after a rebuild unlinks its pathname. It does not adopt an arbitrary replacement binary or replay work. Peer-derived legacy readiness checks use the connected socket PID and do not scan user processes. Automatic version handover rechecks the original authenticated peer on the shutdown connection and uses the existing verified legacy signal path only for its specific unsupported-shutdown response. Schema migration refuses active old runs before shutdown; compatible independent runners survive.

The Codex local development MCP command is an absolute path into the owned stable installation, not an unexpanded plugin-root variable. Cached MCP depends on this path remaining present. Local real-loader checks run in isolated HOME/CODEX_HOME, without model requests, credentials or real ChatGPT Desktop endpoints. Independent OS packages are cancelled; no online plugin submission/upload is performed now.

Legacy shutdown is only reached after the original peer rejects the exact IPC shutdown operation. Same-UID/socket/root ownership, the original boot/start identity, native daemon executable/mode and a healthy known legacy response are rechecked before SIGINT. A pidfd pins the process against PID reuse; the signal never targets a process group. No broad kill, force kill or process-name scan is used. The trusted local-user model remains; this is not cryptographic product attestation. Explicit stop authorization is separate from install --apply.

## Recovery, renewal and host plugins

Notification recovery uses trusted explicit caller identity, the same endpoint owner/fingerprint/capability checks, and exact logical/caller/host matching. Delivery-time renewal is opted in and rechecks invalidation and the current claim after its network probe. Audits commit with the state change. Neither mechanism adds host attestation, endpoint discovery or confirmed Agent-resume evidence.

## Bundle and npm distribution

Offline plugin bundles contain native code and unbound templates, not the author's selected state or secrets. Layout, OS/architecture/ABI and SHA-256 checks detect unsupported or altered contents; hashes are not signatures or publisher authentication and do not establish cross-distribution libc compatibility. Only install trusted builds. Bootstrap preflights installation/marketplace ownership, then applies separate writes; errors preserve completed installation work and identify the next operation to retry. Plugin bootstrap/update always retain an existing recorded state despite shell overrides and refuse downgrade through the new management path. Cached terminal and MCP launchers point to the same managed executable; reconnect loaded MCP after updates. No network download, silent daemon stop, implicit state migration or automatic rollback is added.

Public host plugins bind the actual caller through tool context or explicit host skill substitution. The OpenCode bridge uses a private instance directory/socket, bounded framing/connections/dedupe and host request deadlines, verifies the owned session/project, and calls only the exact public session API. No raw output enters completion messages. Identity remains a trusted same-user declaration, not cryptographic attestation; receiver dedupe across plugin restart is unproven. Claude's scaffold is inbox-only and rejects unexpanded session placeholders. Account-free tests use isolated HOME/config/state and a simulated local model, not a real provider or account. See [host plugins](host-plugins.md).

Shared npm candidates contain the native executable, not selected state or secrets. The wrapper checks platform, required glibc, package/manifest version and native hash before execution; hashes are not signatures or publisher authentication. The self-hosted plugin pins an exact version and an explicit official registry with package scripts disabled. First use contacts npm and marketplace refresh contacts GitHub; this is distinct from the core's local execution/IPC and adds no telemetry service. Review publisher identity/provenance before use. Default host state stays outside npm/plugin caches, with no automatic old-profile migration or data purge. Package installation has no runtime hook; new runtime-starting entries replace an older daemon in that same profile under the startup lock. A package manager may remove cached bytes; current Linux daemons/runner launch use their loaded image, not an arbitrary replacement. Do not use offline receipt-repair commands against npm caches.

## Manual release authorization

Push/PR CI is read-only verification. Only maintainers manually invoke Prepare Release and Publish Release on main. Preparation derives Cargo versions, tests native packages and seals an immutable candidate without npm credentials. Publish Release uses the release environment and actual workflow-bound OIDC identity; its default dry-run has read-only repository permission and changes no registry/release state. Only its separately authorized publication job gets repository content-write permission, and no stored npm publishing token is supplied or used as a fallback. Payload/source/integrity/channel checks fence candidate reuse; exact tooling-only recovery preserves original bytes. Matching existing content is retained, foreign assets/tags stop without overwrite, and GitHub publication follows verified upload acceptance; public availability is checked separately without repeating publication. First-package manual bootstrap is a maintainer exception with interactive authentication/2FA. See [release operation](release.md), [contributor policy](../CONTRIBUTING.md) and [ADR 0013](adr/0013-unified-manual-release.md). Windows runtime evidence remains separate from host/model acceptance.

## Automatic data maintenance

Archives preserve original command specifications, environment overrides, logs and notification/audit history under the same private profile. Gzip and SHA-256 establish compression/integrity, not confidentiality or publisher authentication. Automatic maintenance never purges archived history. Only recorded completed backups that still match their manifest/inventory can be rotated; unknown/changed content stops recovery or removal. Recorded unsealed backup staging is disposable and may be rebuilt. Restore requires a new profile, classifies old active intents as orphaned, invalidates registrations and fences claims before publication; it does not replay commands or resend accepted notifications. See [data maintenance](data-maintenance.md) and [ADR 0014](adr/0014-automatic-data-maintenance.md).

## Local Web access and monitor control

The default-on Web UI binds only 127.0.0.1 on a random port and requires an unpredictable per-daemon bearer credential for every API/SSE request. Only explicit private IPC ui_info returns it; ordinary doctor/MCP diagnostics omit it. Browser bootstrap uses a URL fragment, session storage and URL cleanup, with no credential in HTTP paths, cookies or Referer. Host/Origin validation, no CORS and a restrictive CSP prevent ambient cross-origin use; logs/evidence render as escaped text. Access URLs grant control of the selected local profile and must not enter chat notifications or public reports. This remains a trusted local-user tool, not multi-user authentication or a remote management service.

HTTP exposes a fixed inspection/rule/stop subset, bounded bodies/pages/concurrency/SSE queues, and embedded assets only. There is no filesystem-serving or arbitrary-command HTTP endpoint. AJR_WEB_UI=off disables the listener explicitly at startup; listener failures are visible in diagnostics and do not stop jobs. UI resources require no CDN or runtime frontend toolchain.

Monitor actions are typed and explicitly configured; output is never interpreted as instructions or executable callbacks. Revision/terminal fences and per-revision trigger claims prevent stale rules from cancelling work. Raw-prefix caps do not disable detection, and retained match windows/tails are bounded. Rule changes, trigger evidence and stop reasons persist with history. Database/runner/containment failures retain the existing diagnostic and unknown-effect limitations; a saved rule or live browser connection is not proof of current runner supervision.

## External execution and authentication

Remote `target_id` identifies a provisioned profile; it is not authentication. SSH host keys/user credentials or an existing authenticated transport establish access. The native helper adds no listener, service, plugin installation or elevation. Transport argv is fixed configuration; workload arguments/cwd/env travel on bounded stdin and are never interpolated into the SSH shell command. Target/request/run/attempt echoes are checked before accepting evidence or issuing exact-run stop. Remote provisioning identity is excluded from backups, so a restored profile cannot silently impersonate its origin. Custom adapters are trusted executables and require independent lifecycle/authentication qualification.

Keep tokens, passwords and keys in the existing SSH/`gh` authentication facilities. Explicit task env is persisted on its execution owner; it is unsuitable for secrets. Raw transport stderr is bounded and discarded; GitHub diagnostics retain fixed categories. Local chat endpoint/identity variables are removed from transport child environments. Workload logs, bounded remote observations and final details remain untrusted data with the same private-storage requirements as local output. The workflow adapter issues GET requests only; stopping an observer grants no workflow cancellation or dispatch authority.

## Scoped goal consent and control (experimental)

Goal waiting records actual user permission through negotiated native input or a revision-fenced cooperative Agent/terminal assertion, distinguishable in authorization_source. Plugin text, silence and defaults cannot approve it. Scope pins the original chat/goal/controller/workspace and bounded job budget; native form tokens cannot be overridden by Agent assertions. The actual Desktop terminal supplies runtime selection. The source captures a canonical executable/profile and bounded executable digest, pins the original session/endpoint snapshot, and exposes only an opaque wait ID through shared MCP. A fixed initialize/get/status-only-set allowlist runs with plugins disabled and bounded frames/deadlines; it never loads a thread, invokes a model or sends an objective/budget. Goal snapshots can contain sensitive objectives and remain in private SQLite/backups; normal summaries/notifications omit them. No real host configuration or service is modified.

Lost mutation acknowledgements are not replayed, backup restore invalidates consent and cancels control intents, and original bindings cannot be moved implicitly. Explicit cancellation cannot recall an already transmitted control/message. Current host RPCs lack generation/CAS, so snapshot checks cannot fully fence identical same-second replacement or verification/write/send races; status-only writes still cannot recreate an absent goal. See [goal waiting](goal-waiting.md) for the consent scope and manual recovery boundaries.
