# Security and data ownership

Trusted single local user; this executes arbitrary commands with that user's permissions. It is not a sandbox, permission broker or multi-user service. No telemetry, TCP execution API, remote worker or automatic host discovery.

Linux state/root directories require same owner and mode 0700; socket 0600 and peer UID check. Files are created under umask 077. Locks and log files use O_NOFOLLOW/O_CLOEXEC. Existing symlink database/configuration/receipt files are rejected. Keep the state directory on a local filesystem supporting SQLite WAL and OS file locks. Do not put it in a shared or attacker-controlled tree. Same-UID malicious processes can read state and invoke commands: out of scope. Ancestor directory replacement by the same user is not a filesystem sandbox.

Commands default to argv execution. Shell requires explicit choice, and cwd is canonicalized and validated. Limits: 8 active jobs, 10000 retained jobs, 1000 session registrations, 16 targets/job, 256 args, 64 environment overrides, 64 KiB spec, 8 KiB event payload, 16 MiB per stdout/stderr file, bounded frames and result pages. Extra output is drained/discarded and truncation recorded. There is no automatic cleanup. Monitor disk space; large retained histories can still consume substantial storage. CPU/memory quotas and escaped-daemon process containment are not provided.

Full inherited environment is not stored; explicit override values are stored in the private database and omitted from status output. Command arguments, working directories, logs and environment overrides can contain secrets. Do not pass secrets in argv; logs are not automatically secret-masked. Do not publish state, logs, setup backups or receipts. Output/event payloads are untrusted data and are never executed as internal instructions. Desktop prompts contain only stable job/event metadata, not command output.

Setup changes only the owned agent-job-relay MCP entry, with private adjacent receipt/lock/backup files. It preserves other settings and refuses modified or unowned entries. Default dry-run has no writes; --apply is explicit consent. JSON formatting may be normalized; TOML foreign comments are preserved. Backups may contain unrelated secrets and remain private. Config and receipt are individually atomic, not a cross-file transaction: interrupted setup may require reviewing the backup/receipt; it fails closed rather than taking over. No service, global PATH, sudo, real config modification or network publishing is performed by development tests.

Desktop endpoint is explicitly supplied, owned and peer-checked; private API compatibility and receiver dedupe remain uncertain. Registration stores a socket fingerprint, not cryptographic host attestation. It never scans other sessions, reads credentials, injects binaries or creates a second Codex writer.

Current-context convenience accepts only inherited CODEX_THREAD_ID and CODEX_APP_TOOLS_PIPE_PATH for opted-in --wake/wake_me=true. These remain trusted caller declarations, not host attestation. Shared MCP processes cannot choose per-chat destinations and must use explicit bindings or the current Agent's terminal-tool CLI. Host capability is probed before executing a wake-enabled job. A missing context/capability is an error, not a weaker notification fallback. On-demand launch uses a private startup lock and a detached daemon boundary; only absent/refused sockets trigger launch. No system service is installed. Shutdown remains owner-only IPC and is excluded from MCP discovery.

Installed plugins and generated MCP entries enforce shared-host mode: no inherited chat environment can authorize an implicit wake. A fresh exact session key comes from the current terminal's inherited context and is passed explicitly over MCP. This remains the trusted local-user model, not cryptographic caller attestation. The CLI binding's --brief form omits private endpoint/registration details.

Local installation stores a state-only profile and SHA-256 ownership receipt, not live host identity or credentials. The wrapper and MCP pin the same profile despite unrelated AJR_STATE_DIR exports. Replacements stage new files and retain backups; modified or foreign contents and symlink paths are refused. Data cannot be nested in the install tree. Runtime locks and active jobs block binary changes. Directory replacements publish private durable journals; explicit repair checks snapshots/profiles/hashes, respects installation/cache locks and refuses altered files. Repair only finishes the recorded replacement, preserves backups/data and never rolls back schemas or stops daemons. Multi-directory/configuration changes and multi-file removals remain non-atomic. Unjournaled/old interruptions require inspection. Host user enablement/removal remains managed by the host. The CLI only refreshes explicitly supplied cache snapshots after checking their installation/state/platform, complete file set and hashes; it never scans or purges caches. Modified/foreign/legacy caches are refused and backups retained. Marketplace setup edits only the owned entry and preserves the existing catalogue and other plugins.

Windows state/files use the current owner SID and a protected DACL admitting only that SID and LocalSystem, with reparse/junction refusal. Local pipes reject remote clients and authenticate peer process-token SIDs; process creation time fences reused PIDs. Daemon/runner CreateProcess disables inherited handles, and runner-owned Job Objects contain workloads before user execution and kill their descendants on runner death. An enclosing non-breakaway host job is refused explicitly. Codex 0.164.0 MCP exhibits that restriction; explicit same-profile `daemon start` in an outside terminal prepares the runtime without a job/session or service fallback. Node/Bun host bridges pin the exact server process and secure owner/DACL before registration; the core verifies the pipe ACL before every exchange. See [ADR 0011](adr/0011-windows-native-runtime.md). Windows write-through publication is not a physical power-loss qualification.

Linux internal child launch executes the mapped `/proc/self/exe`, retaining the same program image after a rebuild unlinks its pathname. It does not adopt an arbitrary replacement binary or replay work. Peer-derived legacy readiness checks use the connected socket PID and do not scan user processes. A legacy runtime is never silently stopped: finish active work before an explicit same-state restart.

The Codex local development MCP command is an absolute path into the owned stable installation, not an unexpanded plugin-root variable. Cached MCP depends on this path remaining present. Local real-loader checks run in isolated HOME/CODEX_HOME, without model requests, credentials or real Desktop endpoints. Independent OS packages are cancelled; no online plugin submission/upload is performed now.

Legacy shutdown is only reached after the original peer rejects the exact IPC shutdown operation. Same-UID/socket/root ownership, the original boot/start identity, native daemon executable/mode and a healthy known legacy response are rechecked before SIGINT. A pidfd pins the process against PID reuse; the signal never targets a process group. No broad kill, force kill or process-name scan is used. The trusted local-user model remains; this is not cryptographic product attestation. Explicit stop authorization is separate from install --apply.

Notification recovery uses trusted explicit caller identity, the same endpoint owner/fingerprint/capability checks, and exact logical/caller/host matching. Delivery-time renewal is opted in and rechecks invalidation and the current claim after its network probe. Audits commit with the state change. Neither mechanism adds host attestation, endpoint discovery or confirmed Agent-resume evidence.

Offline plugin bundles contain native code and unbound templates, not the author's selected state or secrets. Layout, OS/architecture/ABI and SHA-256 checks detect unsupported or altered contents; hashes are not signatures or publisher authentication and do not establish cross-distribution libc compatibility. Only install trusted builds. Bootstrap preflights installation/marketplace ownership, then applies separate writes; errors preserve completed installation work and identify the next operation to retry. Plugin bootstrap/update always retain an existing recorded state despite shell overrides and refuse downgrade through the new management path. Cached terminal and MCP launchers point to the same managed executable; reconnect loaded MCP after updates. No network download, silent daemon stop, implicit state migration or automatic rollback is added.

Public host plugins bind the actual caller through tool context or explicit host skill substitution. The OpenCode bridge uses a private instance directory/socket, bounded framing/connections/dedupe and host request deadlines, verifies the owned session/project, and calls only the exact public session API. No raw output enters completion messages. Identity remains a trusted same-user declaration, not cryptographic attestation; receiver dedupe across plugin restart is unproven. Claude's scaffold is inbox-only and rejects unexpanded session placeholders. Account-free tests use isolated HOME/config/state and a simulated local model, not a real provider or account. See [host plugins](host-plugins.md).

Shared npm candidates contain the native executable, not selected state or secrets. The wrapper checks platform, required glibc, package/manifest version and native hash before execution; hashes are not signatures or publisher authentication. The self-hosted plugin pins an exact version and an explicit official registry with package scripts disabled. First use contacts npm and marketplace refresh contacts GitHub; this is distinct from the core's local execution/IPC and adds no telemetry service. Review publisher identity/provenance before use. Default host state stays outside npm/plugin caches, with no automatic old-profile migration, daemon stop or data purge. A package manager may remove cached bytes; current Linux daemons/runner launch use their loaded image, not an arbitrary replacement. Do not use offline receipt-repair commands against npm caches.

Push/PR CI is read-only verification. The Release candidate workflow is manual-only, validates requested versions/tags, and optionally creates a new prerelease draft with narrowly scoped content-write permission. It neither overwrites releases/assets nor publishes npm packages. Release preparation and test registries run without production credentials. The maintainer explicitly authorized a normal Windows VM Rust installation for native verification; current Windows runtime evidence is recorded separately from host/model acceptance.
