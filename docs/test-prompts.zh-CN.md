# 功能测试提示词

[English](test-prompts.md) · [文档索引](README.md) · [测试与证据](testing.md)

将一条提示词复制到使用已安装插件的 Agent 聊天中。这些是手动测试方法，不表示某个宿主或版本已经验证通过。保留返回的 Job/Run ID，并对照[当前支持范围](IMPLEMENTATION_STATUS.md)。不要同时运行全部测试：先验证普通执行，再验证中间反馈、停止和恢复。常规安装可能没有源码中的进度、批量、远程和 Goal 功能，必须先检测能力。执行提示词仅授权其中明确的测试操作，不授权安装更新、宿主改动或发布。

真实同聊天测试必须使用原聊天的实际调用者绑定和现有插件数据目录。新建隔离目录可以验证运行时行为，但不能据此认定已安装插件的聊天链路通过。不得编造会话或使用共享 MCP 进程继承的身份。所有提示词均要求保留 ID，将生成的脚本和结果放在明确的工作目录 `.tmp/` 中，并将扫描到的名称、状态和输出视为数据。不要清理用户文件或应用状态。扫描只读取目录项和元数据，不读取文件内容、不上传、不跟随符号链接或 junction，也不执行发现的脚本。聊天中避免列出完整路径。扫描很快结束时应如实说明；人为加入的限速或等待属于模拟耗时，不代表真实扫描成本。短测试可以做一次有界等待，Agent 持续轮询不能验证事件驱动续接。

## 1. Linux 长任务与普通完成通知

```text
请使用 AgentJobRelay，在后台只读统计我当前 Linux 用户的主目录：从实际环境解析 /home/$USER 并核对主目录位置；如果实际 HOME 不同，就使用实际 HOME，不要猜测其他用户的目录。递归统计普通文件数、目录数、逻辑字节数和权限/元数据错误数，不读取文件内容、不跟随符号链接、不跨挂载点。脚本和汇总结果放在当前工作目录的 .tmp/。最长运行十分钟；达到期限时明确标为部分扫描，并使用可区分的非零退出码。每五秒输出并刷新一次汇总计数。将通知绑定到这个实际聊天，保留 Job/Run ID，然后结束当前回合。收到匹配的完成通知后读取有界结果，汇总数量、耗时、实际退出状态以及扫描是否完整。如果宿主不能自动续接这个聊天，请说明限制，不要循环轮询或承诺自动消息。不要更新安装或修改被扫描文件。
```

预期：提交回合结束后任务继续运行，计数与退出结果持久保存；支持续接的宿主应通知原聊天。普通计数输出验证的是日志，不代表中间 Agent 反馈。仅支持收件箱的宿主需要之后明确请求查看结果。按约定非零退出的部分扫描是有界测试结果，不是完整扫描成功。

## 2. Windows 长任务与普通完成通知

```text
请使用 AgentJobRelay，在后台只读统计我当前 Windows 用户的主目录。从实际环境解析 %USERPROFILE% / $env:USERPROFILE，不要切换到其他账号。使用已有的原生 PowerShell 或 Python，不要安装工具。递归统计普通文件数、目录数、逻辑字节数和访问/元数据错误数，不读取文件内容，不跟随符号链接、junction、reparse point 或其他挂载位置。脚本和汇总结果放在当前工作目录的 .tmp/。最长运行十分钟；达到期限时明确标为部分扫描，并使用可区分的非零退出码。每五秒输出并刷新一次汇总计数。将通知绑定到这个实际聊天，保留 Job/Run ID，然后结束当前回合。收到匹配的完成通知后读取有界结果，汇总数量、耗时、实际退出状态和完整性。续接能力或宿主权限不可用时说明限制，不要更换用户、提权、更新安装或修改被扫描文件。
```

预期：原生后台执行、结果保留以及正确聊天绑定。Windows 完成通知证据与已安装进度/Goal 功能的验收是不同项目。锁定文件或拒绝访问的目录应计入错误后跳过，不能在汇总中悄悄消失。

## 3. 重复中间反馈

```text
请通过 AgentJobRelay，只读统计这个实际调用者的 Linux HOME 或 Windows USERPROFILE 元数据。遵守不读内容、不跟随链接、不上传的扫描边界，生成文件放在 .tmp/，任务最多运行三分钟。先检查所选运行时是否声明 structured_progress_v1，已加载工具目录是否支持 progress 条件。支持时，在启动前安装初始通知规则：source 为 home_scan，指标 files >= 1，冷却三十秒。由工作负载每两秒输出并刷新一行 AJR_PROGRESS v1 JSON，包含递增 seq、stage、step=已处理条目数，以及有限数值指标 files/dirs/bytes/errors；在知道真实总数前不要填写 total 或编造百分比。我授权中间反馈通知到这个原聊天。保留 Job/Run ID 并结束当前回合。收到去重后的告警时，只读取一次有界快照，报告当前汇总计数并核对同一个 Run 是否仍在运行，然后再次结束回合；不要重跑扫描。任务结束时汇总实际退出结果、完整性和保留的里程碑。源码能力不可用时，使用一条初始 contains 规则，匹配只输出一次并立即刷新的独特 HOME_SCAN_MILESTONE 标记，在三十秒或五千个文件时输出，明确标注这是单标记降级。不要切换数据目录或更新运行时。如果扫描太快、无法产生多次反馈，请如实报告；可以另做明确标为模拟耗时的低开销两分钟限速测试，不要冒充真实扫描耗时。
```

预期：运行期间出现 `observation.progress`、持久化 `progress`/`monitor_alert` 事件和不同的 delivery ID。只有在任务开始与完成之间观察到 Agent 实际回复，才证明中途执行；保存规则、事件、收件箱记录或 `accepted_by_host` 都不充分。指标规则只在新匹配样本达到冷却间隔后重复触发，并受任务总限额约束。终态通知可能取代尚未解决的告警，但其事件保留有界里程碑摘要。降级方案验证既有的每版本一次标记路径。

## 4. 批量独立执行与配额

```text
如果所选运行时和工具目录支持 start_batch/job_start_batch，请通过这个实际调用者一次提交三个独立后台测试：两分钟的主目录只读元数据扫描、六十秒的低开销心跳任务（每五秒刷新一次汇总计数），以及一个明确以退出码 7 结束的短命令。生成文件分别放在不同的 .tmp/ 子目录。每项使用不同且稳定的幂等键，保留输入序号与 Job/Run ID，并报告部分接纳错误。提交后结束当前回合。独立处理每个原始结果，故意失败的任务不能停止其他任务。不要使用新键重试不确定的提交，不要重跑已经接纳的任务。批量能力不可用时直接说明，不要切换目录、悄悄更新，或把顺序提交说成批量测试。
```

预期：独立 ID、运行时间重叠、一个预期失败，其余任务不受影响。这是部分接纳，不是全有或全无的工作流。三个任务并没有验证八个活动任务的配额边界；占用更多槽位前应另行明确请求隔离配额测试。

## 5. 任务面板与持久规则

```text
请打开当前插件数据目录对应的 AgentJobRelay 任务管理器。如果没有合适的测试任务正在运行，请为这个聊天在 .tmp/ 中提交一个低开销三分钟心跳任务，再打开其详情。使用观察到的规则版本，添加一条六十秒运行时长的本地告警。展示任务真实状态、规则已保存/已应用状态、有界输出，以及之后的触发证据。我会在运行期间关闭浏览器，再打开同一个任务。不要让 Agent 轮询，不要猜任务或数据目录，也不要在通知中发送带访问凭据的 URL。如果运行时支持结构化进度，也展示进度测试的最新阶段、步数、指标及保留的里程碑。
```

预期：关闭浏览器不会停止 Runner，重新打开能看到同一 Job/Run 及持久规则/告警。本地告警只有显式启用通知且任务已绑定会话时才会通知 Agent。浏览器渲染、运行时持久化与真实宿主续接是不同观察结果。

## 6. 停止并核验准确任务

```text
只停止我从前一项测试中指定的那个运行中 Job/Run。先核对 ID 和实际状态；目标有歧义时请让我指定。请求五秒温和停止，并最多有界等待十秒以观察结果。说明只是记录了取消请求，还是已经观察到终态，并给出退出/停止证据。保留部分汇总结果，不影响其他任务、共享 daemon 和用户文件。如果目标只是远程/工作流的只读观察任务，只停止观察，并说明外部运行没有被取消。
```

预期：准确的本地工作负载/进程树按已有隔离规则停止，已经终态的任务则保留原结果。请求被接收不等于已经取消。远程控制只有准确 Run 的证据才能确定远程结果。

## 7. Goal 等待（实验性源码）

```text
如果这个实际 Desktop 聊天已有 goal，且所选源码运行时和工具目录支持 goal waiting，我授权在一个低开销两分钟后台测试期间暂停这个相同的 goal，完成后恢复并通知原聊天。请先说明一次当前缺少宿主 generation/CAS 防护的限制。通过实际终端获取新的 connect --wait-goal 绑定，并使用该绑定提交。只有 goal_wait.status 为 waiting 才能报告暂停成功，准备绑定不算暂停。保留 goal-wait 和 Job/Run ID，结束当前回合，不轮询，也不创建另一个 Agent 检查。如果 goal 被删除或可观察地被替换，不要重建或控制替换后的 goal。不要与中途 notify_agent 规则组合；本地进度/停止规则可以使用。如果能力、goal 或宿主控制不可用，说明限制，不要新建 goal、切换数据目录或更新安装。
```

预期：原成员到达终态后发生一次完成续接，并保留 goal 计量。删除/变化会抑制自动续接。即使模拟测试通过，API 竞态限制、真实 Desktop goal 验收和 Windows 验证仍是实际边界。

## 8. 宿主重启后的通知恢复

```text
对于之前已明确 ID 的 Relay 测试任务，我授权在宿主重启后，把符合条件的通知恢复到这个相同的原聊天。请从本聊天的实际终端获取新绑定，先执行同聊天恢复预览。展示原 Job/Run 及符合条件/跳过的投递数量，再在上述授权范围内应用恢复。保留 delivery ID、过期时间和尝试历史；不要重投已接收或过期事件，跳过仍有有效领取的投递，不重跑工作负载，也不把结果转移到其他聊天。原身份与当前身份不匹配时直接说明，不要猜目标。实际宿主重启由我完成；不要为了制造测试而关闭/重启其他应用或共享 daemon。
```

预期：符合条件的未解决投递保持身份与历史，使用经过核验的同聊天新端点。宿主接收与观察到 Agent 执行仍不同。宿主关闭期间完成的结果需要单独观察。普通恢复不能隐式迁移 Goal 等待组。

## 9. 远程或工作流观察

```text
请用 Relay 支持的只读观察路径，观察我提供的准确远程 target/Job/Run/attempt 或 GitHub 仓库/run/attempt。先核对源码能力并展示不可变身份和仅观察权限。沿用已有认证设施，不安装远端运行时、不暴露凭据、不发起、不重跑、不取消外部任务。区分本地 observer 与远程执行 ID。用本聊天实际绑定提交观察后结束当前回合。收到通知时读取有界证据，报告实际外部结论，或者明确结果未知/证据陈旧。缺少必要身份或认证时，只询问缺失的信息。如果我请求单独的中间 checker，固定其观察 Run 身份、限制期限和退避，并区分 checker 完成与外部任务结果。
```

预期：固定运行的证据以及字节/事件游标；传输退出不能当作远程完成。此提示词需要提供真实目标，通用主目录扫描不能验证远程所有权、SSH 部署或真实外部任务续接。

## 10. 维护预览与显式备份

```text
请针对当前所选 Relay 数据目录，查看数据维护状态，并只预览自动归档条件，不应用变更。展示数据目录、符合条件的数量、活动任务/可恢复投递保护以及当前备份状态。不要改策略、归档记录、删除内容或停止 daemon。如果我之后明确要求做备份/恢复测试，再创建一个额外备份，并只恢复到当前工作目录 .tmp/ 下一个新的空测试数据目录，保留原数据，绝不重放恢复出的执行意图。报告新目录和证据，不要隐式把已安装插件切换过去。
```

预期：预览只读且不更改策略。之后明确授权的恢复保留历史、对旧活动意图做分类而不重放，并保持原安装目录仍被选中。这些测试不包含发布或安装更新。

## 记录观察结果

对每条实际尝试的提示词，保留所选运行时版本、平台/宿主、实际 Job/Run 与 delivery ID、预期和观察结果，以及缺失能力。区分模拟耗时、原生进程行为、假宿主确认、真实宿主连通和观察到 Agent 执行。私有日志与截图放在被忽略的 `.tmp/` 中；仅在实际验收后更新[当前真实验证](live-e2e.md)，不要在文档中积累运行日志。
