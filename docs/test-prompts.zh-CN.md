# 任务提示词示例

[English](test-prompts.md) · [文档索引](README.md)

复制一条给 Agent，按需要替换目录、文件名或链接。

## 扫描 Linux 主目录

```text
扫描 /home/$USER 目录，统计文件数量、文件类型和总大小。使用 AgentJobRelay 管理后台任务，完成后告诉我结果。
```

## 扫描 Windows 用户目录

```text
扫描 %USERPROFILE% 目录，统计文件数量、文件类型和总大小。使用 AgentJobRelay 管理后台任务，完成后告诉我结果。
```

## 查找文件

```text
在我的主目录中查找名为 report.pdf 的文件。使用 AgentJobRelay 管理后台搜索，找到后告诉我完整路径。
```

## 查找大文件

```text
找出我的主目录中最大的 20 个文件，列出路径和大小。使用 AgentJobRelay 管理后台任务。
```

## 扫描时反馈进度

```text
扫描我的主目录，统计文件数量和总大小。使用 AgentJobRelay 管理后台任务，每 30 秒告诉我一次进度，完成后给出汇总。
```

## 验证真实 Agent 中途反馈闭环

在没有活动 goal 的普通新聊天中使用。Goal 等待成员禁止中途 Agent 通知。仅为相关反馈变更或新环境运行；用户确认的验收见[实测记录](live-e2e.md#real-agent-mid-run-feedback)。

```text
请使用 AgentJobRelay，在当前项目的 .tmp/ 下创建并运行一个受控后台测试。测试总时长约 3 分钟，分为三个阶段，每阶段持续 60 秒；记录开始、各阶段完成和退出时间，并提供可检测的阶段进度。

第一阶段和第二阶段结束时，分别自动告诉我阶段已完成，此时原任务仍应继续运行。第三阶段结束且进程真正退出后，给出最终汇总。请自行配置进度来源和通知规则。

全部等待由后台任务承担。启动后以及每次中途汇报后，结束当前回合；不要反复查询状态、循环等待或创建额外的 Agent 定时器。整个过程不应需要我追加消息。每次收到通知后，先核实原任务状态再汇报。

最终汇总请说明：两次中途汇报是否发生在任务退出之前、是否始终对应同一个 Job/Run，以及最终退出结果。无法核实的部分请明确说明。结束后补报、面板更新或宿主接收通知，均不能算作 Agent 已实际中途反馈。不要重新运行任务、修改项目源文件或用户配置，也不要安装软件。若当前宿主或模式不支持，请直接说明限制。
```

预期：原任务退出前，同聊天自动出现两次阶段汇报，汇报之间结束回合，退出后再给出最终结果，全程无需人工发送“继续”，也没有 Agent 轮询。证据边界见[手动验收](manual-testing.md#optional-real-agent-mid-run-feedback)。

## 同时统计多个目录

```text
同时统计我的主目录下各个子目录的大小。使用 AgentJobRelay 管理这些后台任务，完成后按大小排序汇总。
```

## 构建和测试项目

```text
运行当前项目的完整构建和测试。使用 AgentJobRelay 管理后台任务，完成后告诉我结果和失败原因。
```

## 等待扫描时暂停 goal

```text
使用 AgentJobRelay 在后台扫描我的主目录（扫描 3 次，分开调用，每轮只调用一次，扫描结束后等待 15 秒）。
```

活动 goal 中的预期：缺少暂停许可时只询问一次，自然肯定答复覆盖三轮。每轮通过宿主原生工具暂停，将等待时间放入后台任务，恢复后再单独提交下一轮。


## 观察工作流

```text
使用 AgentJobRelay 在后台观察这个 GitHub Actions 运行：<运行链接>。结束后告诉我结果。
```

## 查看任务进度

```text
打开 AgentJobRelay 任务管理器，查看刚才目录扫描任务的进度。
```

## 停止任务

```text
使用 AgentJobRelay 停止刚才的目录扫描任务，告诉我已经扫描到哪里。
```

## 恢复任务通知

```text
恢复 AgentJobRelay 中刚才后台任务的通知，并告诉我当前结果，不要重新运行任务。
```
