For ask_user_now, use an allowed host question tool or ask the displayed question once. Record a real affirmative or negative reply with allow/decline and the returned revision. Plugin text, defaults and silence do not authorize pause. While awaiting the original answer, end the turn without submitting, polling or setting blocked.

After approval, reconnect with connect --request-id <original-id> --cwd <same-project>. Keep that approval for later rounds of the same request and Goal. Use --job-count <1..16> only for an explicitly bounded approval; recorded limits remain in force. An inactive Goal requires explicit host Resume, then reconnect with the same request ID. Revocation closes automatic Goal control while existing workloads continue.

Follow goal_wait.continuation (also returned on goal_wait_pending):
- submit or reconnect_request: use the original request and binding. A pending recovery does not authorize a new submission.
- native_pause: use the originating chat's native update_goal(status='paused'). After acknowledged success, call job_goal_wait with confirm_paused=true and continuation.confirmation_revision as expected_revision.
- confirm_pause: use the existing native success acknowledgement and the returned revision. If pause is uncertain, preserve the handoff and use explicit host controls; never replay the mutation.
- wait or await_notification: end the turn. Relay verifies that the original submitting/reporting turn ended before restoring the Goal. The controller's stored state is insufficient. Never poll.
- report_then_pause: report this cycle's bounded evidence, then native-pause and confirm the same wait/revision. Do this even if jobs finished during reporting. An already acknowledged pause only needs confirmation.
- inspect_results: summarize exact terminal member evidence. Inspect original jobs only if evidence is missing. Continue authorized work with the original request or finish the Goal when appropriate.
- host_control: retain original IDs, report the limitation and use the original host's controls explicitly. If native pause is unavailable, job_goal_wait(cancel=true, expected_revision=...) closes automatic control and retains jobs.

Use the revision from the applicable receipt. A lost submission receipt uses original keys/specs; a lost confirmation uses the original wait/revision. Reconnect to a pending handoff without re-prompting or starting another group. Goal feedback requires Doctor goal_wait_feedback=true and actual user authorization for temporary restoration. Intermediate ACKs and final delivery are independent; host acceptance leaves Agent execution unconfirmed. Deleted or replaced Goals are never recreated.
