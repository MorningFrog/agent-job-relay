Use spec.command.kind=remote with the configured target and pinned launch or attach intent. Remote cwd, env and rules belong in remote.intent.spec on launch. Preserve origin IDs, durable launch keys and exact target/run/attempt across reconnects. Retry the original submission key/spec after response loss. Transport loss is not a remote outcome. Only controlled runs can be stopped; stopping read-only observation leaves the external run active.

For GitHub Actions use kind=github_actions with a fixed workflow attempt. For Woodpecker use kind=woodpecker with server, repository, global pipeline ID, number and full commit. Both are read-only. Keep credentials in the configured environment/token references.

For direct native remote feedback require origin Doctor remote_alert_feedback=true. Configure remote rules in remote.intent.spec.monitor_rules with notify_agent=false and an outer origin spec.monitor_rules entry {condition:{kind:"remote_alert",rule_id:null,cooldown_seconds:600},action:"alert",notify_agent:true} with the actual caller binding. Optional rule_id selects one remote rule. Live edits require the observer capability. Remote alerts preserve original provenance and are coalesced/bounded; they cannot grant Goal/stop authority or choose the chat. Honor completion-only and Goal feedback authorization. Use job_inspect remote_feedback for evidence if the notification is insufficient.
