# AgentJobRelay for ChatGPT Desktop/Codex

Self-hosted experimental plugin marketplace, separate from OpenAI's official directory. Requires a local Linux x86_64/glibc or Windows x86_64 executor and Node.js 20+/npm on the host's PATH. The pinned shared runtime is fetched from the official npm registry on first use, includes the Rust binary and runs no package install scripts. First use requires network access. No Rust compiler or developer checkout is needed.

After the runtime and marketplace version are published, add the repository with `codex plugin marketplace add MorningFrog/agent-job-relay`, then restart ChatGPT Desktop and install AgentJobRelay from the **AgentJobRelay** marketplace. Use a new local chat. Installation/UI availability depends on your host version/account. CLI users can use `codex plugin add agent-job-relay@agent-job-relay`; that alone provides no automatic CLI model continuation.

The MCP server and packaged `relay` terminal launcher use the same runtime version and persistent `codex` profile. Default state on Linux is `$XDG_STATE_HOME/agent-job-relay/codex`, else `$HOME/.local/state/agent-job-relay/codex`; Windows uses `%LOCALAPPDATA%\AgentJobRelay\profiles\codex` and the `relay.cmd` terminal launcher. An absolute `AJR_STATE_DIR` overrides it and must match in the ChatGPT Desktop process and terminal. Keep history outside npm/plugin caches. A previous offline installation has a different recorded profile: do not enable both or switch profiles as a repair. Review and explicitly select the original state if migrating.

Windows normally needs no manual daemon preparation. When Codex's MCP cleanup Job Object blocks direct startup, the native runtime automatically requests a local CIM bootstrap, verifies the same user/integrity/process identity, transfers the caller environment over a private pipe and starts the same profile. No login startup entry, scheduled task or service is installed. Windows PowerShell/CIM must be permitted by local policy; `AJR_WINDOWS_STARTUP=direct` disables the broker. If blocked, run same-profile `daemon start` in an outside terminal. The offline v0.1.8 workflow is verified with Windows ChatGPT Desktop using Full access; this online candidate still needs public-registry acceptance after publication.

The workflow obtains a fresh binding from the initiating chat's terminal, never from the shared MCP process. Background commands run with your OS permissions. ChatGPT Desktop completion uses an experimental private interface, not a public stability guarantee. Host acceptance does not establish that an Agent resumed; CLI integration provides an inbox only. No telemetry service is added, but npm/GitHub handle package/repository downloads, and the host/model can receive results you explicitly inspect.

For upgrades, finish active jobs, deliberately select the new marketplace/runtime version and reconnect MCP. An incompatible daemon requires an explicit same-profile stop; no automatic stop, rollback or command replay runs. Refresh the marketplace with `codex plugin marketplace upgrade agent-job-relay`. Host/cache removal preserves state/history and running jobs. Remove the plugin through the host, then remove the marketplace if no longer wanted. For maintenance and observed support boundaries see [installation](https://github.com/MorningFrog/agent-job-relay/blob/main/docs/installation.md).
